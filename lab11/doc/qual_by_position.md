# qual_by_position.py 사용 설명서

## 1. 개요

`src/qual_by_position.py` 는 FASTQ 파일의 **모든 read 에서 같은 위치(1번째 염기, 2번째 염기, ...)의 품질 점수를 모아 위치별 평균 품질**을 계산하는 스크립트이다.

- 결과는 `위치<TAB>평균품질` 형식으로 한 줄에 한 위치씩 출력한다.
- FastQC 의 "Per base sequence quality" 그래프에 들어가는 값(위치별 평균)을 직접 계산해 보는 것과 같다.
- 표준 라이브러리(`sys`)만 사용하므로 별도 설치 없이 실행된다.

## 2. 사용법

lab11 폴더 안에서 실행한다.

```bash
cd lab11
python3 src/qual_by_position.py <FASTQ 파일 경로>
```

FASTQ 파일을 주지 않으면 사용법을 안내하고 종료한다.

### 2-1. 실행 예시

```bash
python3 src/qual_by_position.py data/SRR1553607_1.fastq
```

출력 결과 (중간 생략):

```
위치	평균품질
1	32.04
2	32.17
3	32.28
4	35.85
5	35.65
...
50	33.44
...
99	29.03
100	28.93
101	28.25
```

### 2-2. 결과를 파일로 저장하기

출력이 위치 개수만큼 길기 때문에 파일로 저장해 두면 편하다.

```bash
python3 src/qual_by_position.py data/SRR1553607_1.fastq > doc/qual_by_position_raw.tsv
python3 src/qual_by_position.py data/trimmed.fastq      > doc/qual_by_position_trimmed.tsv
```

탭으로 구분된 파일(`.tsv`)이므로 엑셀·구글 시트에서 열어 그래프를 그릴 수 있다.

## 3. 출력 형식

| 열 | 설명 |
|----|------|
| 위치 | read 안에서 몇 번째 염기인지 (1부터 셈) |
| 평균품질 | 그 위치를 가진 모든 read 의 Phred 품질 점수 평균 (소수점 둘째 자리까지) |

품질 점수는 **Phred+33** 인코딩으로 계산한다.

```
Q = (품질 문자의 ASCII 코드) - 33      예) 'I' -> 40, '#' -> 2
```

## 4. 계산 방법: 길이가 다른 read 처리

트리밍한 파일처럼 read 마다 길이가 다를 수 있다. 이 스크립트는 **위치마다 두 가지 값을 따로 센다.**

- `sums[i]` : i 번째 위치의 품질 점수 합계
- `counts[i]` : i 번째 위치를 **가진** read 의 수

```
위치별 평균 = sums[i] / counts[i]
```

예를 들어 다음 두 read 가 있다면

```
read1 품질: II##   (길이 4, 점수 40 40 2 2)
read2 품질: 55     (길이 2, 점수 20 20)
```

| 위치 | 점수들 | read 수 | 평균 |
|------|--------|---------|------|
| 1 | 40, 20 | 2 | 30.00 |
| 2 | 40, 20 | 2 | 30.00 |
| 3 | 2 | 1 | 2.00 |
| 4 | 2 | 1 | 2.00 |

3·4번째 위치는 read2 에 없으므로 read1 의 값만으로 평균을 낸다.
"가장 짧은 read 길이까지만 계산" 하는 방법과 달리, 긴 read 의 뒷부분 정보도 버리지 않는다.

## 5. 결과 해석 예시

트리밍 전(`SRR1553607_1.fastq`, 모든 read 101 bp)과 후(`trimmed.fastq`, read 길이 50~101 bp)를 비교하면:

| 위치 | 트리밍 전 | 트리밍 후 |
|------|-----------|-----------|
| 1 | 32.04 | 32.25 |
| 3 | 32.28 | 32.49 |
| 101 | 28.25 | 29.97 |

- 두 파일 모두 **3′ 끝(뒤쪽 위치)으로 갈수록 품질이 떨어지는** 전형적인 Illumina 패턴을 보인다.
- 트리밍 후에는 같은 위치의 평균이 더 높다. 품질이 낮은 부분과 read 가 제거되었기 때문이다.

## 6. 코드 구조

| 함수 | 하는 일 |
|------|---------|
| `qual_by_position(filename)` | FASTQ 를 한 줄씩 읽어 4번째 줄(품질 문자열)마다 위치별 합계·개수를 더하고 `(sums, counts)` 를 돌려준다 |
| `main()` | 명령줄 인자를 확인하고, 위치별 평균을 탭으로 구분해 출력한다 |

파일 전체를 한꺼번에 메모리에 올리지 않고 **한 줄씩** 읽기 때문에 큰 FASTQ 파일도 처리할 수 있다.

## 7. 주의할 점

- **Phred+33 전용**이다. 아주 오래된 Illumina(1.3~1.7) 의 Phred+64 데이터에서는 점수가 31만큼 크게 나온다.
- FASTQ 가 **정확히 4줄에 read 하나**인 형식이라고 가정한다. 서열이 여러 줄로 나뉜 FASTQ 나 빈 줄이 섞인 파일에서는 엉뚱한 줄을 품질로 읽는다.
- 압축 파일(`.fastq.gz`)은 바로 읽지 못한다. 먼저 `gunzip` 으로 풀거나 `zcat` 으로 풀어 저장한 뒤 사용한다.
- 뒤쪽 위치일수록 그 위치를 가진 read 수가 적을 수 있다. read 수가 아주 적은 위치의 평균은 몇 개 read 에 크게 좌우되므로 해석에 주의한다.
